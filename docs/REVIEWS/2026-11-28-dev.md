## Findings

### P2 — World shortcuts swallow Space on focused buttons

Location: `web/src/features/safari/world/SmoothOverworld.tsx:97-104`.
Introduced with `23b17ca`.

The key handler excludes text inputs, but accepts events from every descendant
of the world root. Space always prevents default and calls `interact()`. With
Pause focused, Space therefore fails to activate the button, while Enter pauses
correctly. Other buttons such as Surf/Land and nearby-Pokémon actions have the
same native keyboard conflict. The issue is in input routing, not animation.

Reproduced in production Chrome: `spacePaused=false`, `enterPaused=true`.
Preserve native activation for interactive descendants, honor already-handled
events, and limit movement/action hotkeys to the world viewport/context. Add
keyboard acceptance checks for Space and Enter on controls, not only Escape and
pointer clicks.

### P2 — Open menus block walking but do not block world actions

Locations: `SmoothOverworld.tsx:85-91`, `:97-107`, and `:116`.
Introduced with `23b17ca`.

The animation loop checks open menus/dialogs before moving, but `interact()` only
checks the explicit Pause flag, lock and traversal transition. Opening Region map
with M leaves focus in the world. E can then start an encounter while Region map
is still open, despite exploration being paused by that menu.

Reproduced with `regionMapOpen=true` and `encounterStarted=true` after M then E.
Centralize the actual world-input permission check and use it for movement,
interaction, traversal and pointer commands, while retaining an intentional
close-menu action. Avoid adding different pause-condition lists in every handler.

### P2 — Spawn-cell changes replace Pokémon that are still visible

Location: `SmoothOverworld.tsx:134-137`; seeded IDs in `world/wild.ts`.
Introduced with `23b17ca`.

The spawn key changes at each six-tile grid boundary. The controller replaces the
entire `wild` array with a new seeded population, including IDs, species rolls,
positions and wandering state. This is independent of whether old entities are
still visible or the player is approaching a particular one.

In a Route 1 production-browser probe, walking only 0.79 tiles across x=18 replaced
all three nearby entity IDs, retaining none. The camera/movement can be smooth
while the target population visibly pops. Retain in-range entities across cell
changes, fill/cull through spatial buckets, and roll new entity identity/traits
once per spawn lifetime. This initially needs in-session continuity, not a new
persistent save for every wild Pokémon.

## Overall system improvements

1. **Measure the real persistence path before expanding progression.**
   `pc/persistence.ts:36` reads all captures with `getAll()` for every command;
   migration/validation and snapshot return scan the collection again. The new
   UI indexes and batch allocator improve lookups/deposit behavior, but are not
   incremental IndexedDB writes. Existing tests cover 10,000 in-memory captures
   and bounded browser rendering with 3,000; these do not establish transaction
   p95 latency for a leader change, nickname or move. Add an isolated browser
   benchmark for end-to-end command latency/allocation before normalizing stores.
   Follow the existing GAMEPLAY_FOUNDATION gate when multi-entity rewards,
   inventory or evolution justify indexed reads and revisioned patches. This is
   a supported scaling concern, not a measured current slowdown.
2. **Use a single input policy as interaction features grow.** The two keyboard
   findings are concrete consequences of separately defining typing/focus,
   modal blocking and explicit pause conditions. Keep it within the world
   controller; an application-wide event bus is unnecessary.
3. **Keep shipped facts distinct from roadmap proposals.** Four Classic regions
   are active; Unova geography is retired; Smooth covers only 23 Kanto/Hoenn
   outdoors. Party/leader metadata and cosmetic highlights are separate. XP,
   evolution, activities and service interiors are not implemented yet. The
   refreshed project memory and AGENTS context now make these distinctions explicit.
4. **Plan release validation separately from dev verification.** This review is
   production-browser verification. Before shipping these commits to existing
   downloads, bump the release version and exercise the packaged updater/install
   path with an isolated older profile, including collection schema migration.
   No publication or packaging was performed by this review.

## Strengths worth preserving

- Party commands read canonical state within one IndexedDB write transaction;
  stale-tab six-member enforcement and migration rollback have behavior coverage.
- Schema v2 preserves old metadata/unknown capture fields and rejects newer
  unsupported versions. The physical database version remains 1.
- Receipt deduplication, unique slots, outbox recovery and SQL isolation remain
  the ownership boundary. Party membership does not change physical placement.
- Physics, terrain parsing, collision rules and rendering are separate modules.
  The current pinned neighborhood estimate peaks around 6.0 MB against the
  12 MiB decoded-asset cache budget; no current neighborhood budget failure was
  substantiated. This estimate is not total browser process memory.
- UI motion honors reduced motion and reuses stable controls/native details.
  Existing focus owners are reused rather than adding animation-driven timers.
